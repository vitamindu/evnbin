# 08 UI 가이드 (모양·구조를 통일하기)

새 화면·팝업을 만들 때 **기존 화면 하나(예: `src/ui/screens/shop.ts`, `fighters.ts`)를 열어 같은 방식으로** 만든다. 새 스타일을 발명하지 않는다.

## 1. 좌표·기기
- 모든 크기는 **1280×800 설계 좌표(px)**. `#ui`가 화면에 맞게 `scale()`한다. `rem`/`vw` 같은 상대 단위를 쓰지 않는다.
- 화면 비율이 다르면 무대가 늘어나므로 **모서리 요소는 실제 화면 모서리에 붙는다.** 1280×712(주소창이 보이는 짧은 화면)에서도 버튼이 안 잘려야 한다(E2E `T-13`).
- 세로로 들면 "기기를 돌려 주세요" 안내가 전체를 덮는다. 세로 레이아웃은 만들지 않는다.
- **터치 전용 설계**: hover 없음, 드래그로 화면이 밀리지 않게 `touch-action: none`(전역). 누르는 곳은 손가락으로 누르기 쉬운 크기로 만든다(기존 버튼은 뒤로 84×62, 카드는 200px대, 작은 칩도 100px 높이쯤). 가로로 긴 목록은 `overflow-x: auto`로 손가락으로 넘긴다(상점 `shop-strip`, 스크롤바는 숨김). `attachDrag`는 캐릭터 모델을 돌리는 드래그용이다(로비·캐릭터 상세).

## 2. 모양 (카툰 스타일)
- **굵은 어두운 외곽선(`var(--ink)` 3px) + 단단한 그림자(번지지 않는 `0 4px 0 var(--ink)`) + 둥근 모서리(16~20px)**. 번지는 그림자, 얇은 선, 각진 모서리를 쓰지 않는다.
- 글꼴은 `--font`(Lilita One + 한글 Black Han Sans). **글자는 `.t-outline`(검은 외곽선)** 으로 쓰고, 외곽선 두께는 `--o`(보통 2px, 큰 글자 3px).
- 색은 `main.css`의 변수만 쓴다: `--ink`(외곽선), `--navy-950~600`(배경), `--panel`(패널 바탕), `--cyan`, `--orange`, `--yellow`, `--green`, `--red`, `--muted`. 새 색이 필요하면 변수로 추가하고 이 문서에 적는다.
- **버튼 색 규칙**: 보통 = 파랑 그라데이션(`#3b4fb8→#24318a`), 주 행동(시작·선택) = 주황(`#ffc04d→#f0620a`), 완료·선택됨 = 초록, 취소·뒤로 = 파랑 `btn-back`. 패널 = `.panel`(어두운 남색 + 안쪽 옅은 선).
- 팀 색: **우리 = 파랑(`is-blue`), 상대 = 빨강(`is-red`)**. 캐릭터 색으로 팀을 구분하지 않는다(보는 사람 기준).
- 등급 색: 서사 = 보라 그라데이션(`#c77dff→#8a3ad1`), 전설 = 금색(`#ffe27a→#f0a21a`) + 은은한 빛. 라벨은 "서사/전설".
- 재화: 코인 = 금색 동전 아이콘, 다이아 = 하늘색 보석 아이콘. 가격 버튼은 `아이콘 + 숫자`.

## 3. 만드는 방법 (공용 도구)
- DOM은 `src/core/dom.ts`의 `el(태그, 클래스, 자식)`로, 글자는 `txt(문자, 클래스)`로 만든다(`innerHTML` 금지).
- 버튼은 `button(클래스, 자식, 동작, 소리)`(`src/ui/widgets.ts`): 탭 판정(8px 미만 이동·250ms 이내)과 효과음(`tap`/`back`/`select`)이 들어 있다. `<button>`을 직접 만들거나 `click`을 쓰지 않는다.
- 공용 위젯: `header(제목, 뒤로, 오른쪽)`(모든 화면 맨 위), `currencyBar`(코인·다이아; 누르면 상점), `roleChip`, `iconEl(이름)`. 아이콘은 `src/ui/icons.ts`의 `ICONS`에 SVG를 추가한다(외부 이미지 파일 금지).
- 화면 = `createXxxScreen(ctx): Screen`(`{ el, bg, onShow, onHide }`)을 만들고 `main.ts`에서 `screens.show`로 연결한다. 팝업 = `src/ui/overlays/`에서 `ctx.overlayLayer`에 붙인다. 바깥을 누르면 닫는다.
- 알림은 `toast(문자)`. 다이아·코인을 쓰는 구매는 **한 번 더 묻는 확인창**(`confirm-panel`, 상점의 `shop-confirm` 참고)을 쓴다. 오류는 `accountErrorText`로 한국어 안내.
- 프로필·설정은 `state/profile.ts`(`getProfile`, `onProfileChange`로 다시 그리기). 화면은 프로필이 바뀌면 스스로 다시 그린다.
- CSS는 `src/styles/main.css`(공통·로비·목록), `online.css`(온라인), `battle.css`(전투 HUD). 클래스 이름은 화면 접두어(`shop-`, `rk-`, `rs-`)를 쓴다.

## 4. 글 쓰는 방법
- 화면의 모든 글은 **한국어**, 짧게(버튼은 2~6글자). 캐릭터·스킨·공격 이름은 영어 대문자 그대로(RIVET, Shadow Step).
- 숫자는 `toLocaleString('en-US')`로 천 단위 쉼표(코인 1,500).
- 안내·오류는 존댓말 한 문장("다이아가 부족해요").

## 5. 전투 화면 (집중을 방해하지 않는다)
- 점수판은 **왼쪽 위 나가기 버튼 옆에 작게**, 모든 모드 공통(`battle.css`). 화면 가운데·위에 큰 점수판을 두지 않는다.
- 이름은 체력바 위, **체력 숫자는 바 안**. KO 알림(kill feed)은 모든 모드에서 `hit.killed` 사건으로.
- 조작 UI(스틱·공격·궁극기)는 손가락이 가리는 위치를 피해서 모서리 쪽에 둔다. 새 HUD 요소는 기존 위치와 겹치는지 스크린샷으로 먼저 본다.
- 탄환·폭탄·스킨 이펙트는 팀 색(우리 파랑/상대 빨강).

## 6. 테스트를 위한 약속
- E2E는 **클래스 이름과 `data-*` 속성**을 쓴다(`data-fighter`, `data-item`, `data-btn`, `data-mode`, `.fcard`, `.shop-card`, `.btn-play` …). 이름을 바꾸면 테스트도 같이 고친다. 새 요소에는 의미 있는 클래스·`data-*`를 붙인다.
- 애니메이션 중 탭은 무시될 수 있다. 테스트는 `getAnimations().finished`를 기다린다.
- 화면을 바꾸면: ① 1280×800과 1280×712에서 요소가 화면 안에 들어오는지(`boundingBox`) ② 스크린샷으로 눈으로 확인 ③ 관련 E2E 실행(먼저 `npm run build`).
- 카드 개수·순서를 세는 테스트(`phase1.spec.ts`, `shop.spec.ts`, `ranking.spec.ts`)는 캐릭터·상품·등급을 추가할 때 깨진다. 같이 고친다.

## 7. 자주 하는 실수
- 캐릭터 목록을 새 줄로 넘기면 화면 아래가 잘린다(현재 5열×2줄 = 10장이 한계, "곧 추가" 카드는 5의 배수가 아닐 때만 나온다).
- 큰 이미지를 DOM `img`로 그냥 쓰면 부팅이 느려진다. 초상화처럼 미리 그려서(`data:` URL) 재사용한다.
- 번역 안 된 영어 문장, 이모지 아이콘, 외부 CDN 글꼴·이미지는 쓰지 않는다(오프라인 PWA).
